# 厨房取可乐优化与复测

日期：2026-10-11 至 2026-10-12。本报告对应 `start_embodied.sh` 的 YOLOE / GraspNet / MoveIt 取物流程。

## 确认的问题

1. 原具身入口的语义点云 `auto` 在 LIO 模式选择 FAST-LIO；该 YOLOE 分支只发布语义地图点云，没有发布 GraspNet 订阅的彩色点云和三维检测。诊断轮 RGB 中可乐可见，但抓取模块收不到候选；扫描也无效。
2. 原导航容差为 25 cm / 0.4 rad。一次独立复测虽然导航成功，机械臂目标却在工作空间边缘；直线接近有、无碰撞检查均只能完成约 68.8%，关节规划返回 GOAL_STATE_INVALID。这次失败不是夹爪摩擦导致。
3. Agent 未使用仿真时间，检测没有严格的新鲜度和多帧稳定性检查。旧流程忽略部分归位、夹爪、抬升、回 Home 结果，可能错误报告成功；原抬升同时大幅向底盘方向移动。

## 最终修改

- 具身入口默认相机深度、sim 深度和 manipulation YOLOE 配置；FAST-LIO 继续定位。拒绝具身抓取配合不提供 GraspNet 输入的 FAST-LIO 语义分支。
- Agent 启用 `use_sim_time`；明确的单步取物指令直接按导航→抓取顺序执行，否定句、条件句和复杂命令仍交给原模型流程。导航失败不会继续抓取。
- 只为具身任务启用精确停车配置：RPP 低速跟踪，位置容差 10 cm、朝向容差 0.10 rad，原地转向 0.35 rad/s。普通导航入口保持原配置。保留碰撞检查及底盘运动调理的物理加速度限制。
- 停车后核验新鲜 map→base_footprint、实际误差 ≤12 cm / 0.15 rad，并要求位姿连续一秒稳定（平移变化 <1 cm、朝向变化 <0.015 rad），结合新鲜里程计和速度界限。
- 抓取使用连续新鲜、同类别的稳定候选，先移到抓取轴前 8 cm，再直线接近；核验闭爪接触后先竖直抬升 12 cm，再持物回 Home 并持续检查两秒。任何阶段失败明确报告；恢复感知与点云过滤。
- 夹爪复用已有动作结果检查，区分接触停滞与打开失败；机械臂动作严格检查 SUCCESS。

未重新训练模型、未修改物体摩擦参数。厨房目标仍使用 map 中的 (3.76, 2.22, 6°)。

## 诊断过程（保留失败）

| 轮次 | 配置与结果 |
|---|---|
| 1 | FAST-LIO 语义，导航成功，抓取候选缺失，检测失败 |
| 2 | 改为深度，原宽松停车；抓取、抬起、持握回 Home 成功，回放可见可乐 |
| 3 | 同上独立重启；目标接近不可达，失败 |
| 4 | Graceful + 4 cm 容差；导航超时 |
| 5 | RPP 小转向加速度；起转缓慢，导航超时 |
| 5b | 在线调整的诊断轮；恢复行驶但超过总导航时限，不计入最终配置 |
| 6 | RPP 较高转向速度；导航到达，停稳检查未通过，抓取未启动 |
| 7 | 4 cm + 无状态位置检查；桌边反复调整，导航超时 |

轮次 4 首次启动时正在编辑启动脚本，导致运行中的 shell 读取位置失效而退出；完整停止后重启，尚未下发任务，不计为任务回合。启动日志也保留。

4 cm 配置在当前滑移转向底盘和扫描定位下过于苛刻，最终采用 10 cm；停稳检查改为位姿窗口，避免静止时 LIO 差分速度噪声误拒收。上述诊断轮使用不同配置，不能汇总为最终成功率，也不能当作公平的原版基线。
