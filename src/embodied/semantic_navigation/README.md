# 探索、持久地图与语义取物

入口：`./start_embodied.sh --pipeline traditional --sim gazebo --no-build`。不预设厨房或其他房间的导航坐标。

首次启动缺少几何地图包时，自动探索并保存全局点云、二维导航地图；已有完整地图包时直接重新定位，不因语义标签尚未确认而重复探索。默认地图包为 `maps/gazebo/semantic_simple_room`，结构化语义信息独立保存于同级 `semantic_simple_room.semantic.json`，可在复用几何地图时继续完善。

普通 OctoMap 只有占用信息。系统将 YOLOE 深度检测和局部语义体素通过 TF 变换到 map 坐标，记录物体类别、位置及重复观测，再将全局二维地图和物体分布投影交给 VLM。VLM 推断房间名称、候选 XY 范围、置信度和证据物体 ID；相机房间观察只作为辅助证据，观察者位置不直接等同于房间位置。当前全局 FAST-LIO OctoMap 用于在线几何建图；跨重启复用的是 map 坐标下保存的 PCD 和二维地图，并未实现直接重载 odom 坐标 OctoMap。

VLM 使用 JSON Schema 约束输出房间枚举和已观测物体 ID；原始回复、输入地图图像保留供审查。候选分区须通过证据物体位置、置信度和最小面积检查，并与已知可通行栅格相交。`bounds_xy` 是候选包围盒，`cell_runs` 是筛选后的可通行区域。开放区域边界可能有歧义；单个杯子或可乐不足以断言厨房。几何连通分区保留作为基础能力，不能替代物体语义判断。

执行链路：保存地图并完成定位 → 查找 VLM 语义区域（缺失时在地图内巡查）→ 地图计算无障碍导航候选 → Nav2 与实际到达核验 → 新鲜图像 VLM 确认房间 → YOLOE 多帧跟踪指定目标 → Nav2 接近 → GraspNet／MoveIt 抓取、抬起、持物回 Home。历史物体位置只用于接近；抓取要求三帧新鲜稳定目标，候选距离约 0.62–0.76 m，最终可达性由 MoveIt 核验。缺少证据时停止，不使用固定坐标兜底。

状态：`/explore/status`、`/semantic_world/state`、网页 `/api/status`。结构化文件包含物体、房间、候选分区、相机观察和地图元信息。

实测记录：全局 PCD 已保存 174,172 点，重启进入已有地图定位模式，未再次启动自动探索。首次完整任务在巡查与房间确认阶段失败，未发出抓取指令；日志与视频位于 `log/semantic_navigation/validation`。发现 VLM 混合房间标签、返回字段缺失及重复选择失败巡查点，已加入结构化输出约束和巡查点去重。完整“语义区域导航→目标跟踪→物理抓取”尚未通过验收，旧固定点成功率不适用于本流程。证据位于 `log/semantic_navigation`。
