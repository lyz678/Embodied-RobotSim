# 探索、持久地图与语义取物

入口：`./start_embodied.sh --pipeline traditional --sim gazebo --no-build`。不预设厨房或其他房间的导航坐标。

首次启动缺少几何地图包时，自动探索并保存全局点云、二维导航地图；已有完整地图包时直接重新定位，不因语义标签尚未确认而重复探索。默认地图包为 `maps/<后端>/semantic_<场景>`，结构化语义信息独立保存于同级 `.semantic.json`，另有等价的 `.semantic.json.gz` 压缩副本，可在复用几何地图时继续完善。

`start_mapping_and_explore.sh` 在探索阶段也启动 Semantic World 和 VLM，使用实际 YOLOE 配置中的类别名称生成摘要。两个入口必须使用相同的仿真后端、场景和 `--bundle`；建图入口默认 Isaac，具身入口默认 Gazebo，应显式指定。示例（建图目录必须尚不存在）：

```bash
./start_mapping_and_explore.sh --sim gazebo --bundle maps/gazebo/home_semantic --llm local --no-build
# 自动探索、地图保存完成后，使用同一地图包启动具身任务
./start_embodied.sh --sim gazebo --bundle maps/gazebo/home_semantic --llm local --no-build
```

保存内容分三层：

| 文件 | 内容与用途 |
| --- | --- |
| `<bundle>/bundle.json`、`map.pcd`、`map.yaml`、`map.pgm` | map 坐标系几何、重定位与 Nav2 |
| `<bundle>/global_octomap.svm` | LIO 探索完成后请求保存的全局 LiDAR 几何及语义体素快照；局部相机图仅在搜物时开启，探索阶段不保存局部图 |
| `<bundle>.semantic.json`、`.semantic.json.gz` | 物体类别及 map 下 XYZ、重复观测、房间范围与可通行栅格行程、证据物体、相机观察、几何指纹和快照保存状态 |

结构化文件是三维语义的摘要，不能从中还原完整体素图。JSON 存在时优先读取，否则读取 gzip；仅几何文件指纹匹配、`frame=map` 的摘要可复用。旧版无指纹的摘要不作为导航证据。`.svm` 保留 odom 坐标，不在新会话自动加载；具身使用 PCD/二维图重定位及 map 下的结构化语义。`voxel_snapshots` 报告保存服务的实际结果，不能仅凭配置了路径断言快照已写入。

`exploration_status=complete` 表示几何探索完成。房间范围未确认时，VLM 根据全局地图、物体分布和相机观察，分别为厨房、书房选择一个估计搜寻点。候选由占据地图生成并核验0.48m净空，模型只选择候选编号，不输出任意坐标或边界。`navigation_hints` 保存估计点、置信度和依据；`semantic_status=search_hints` 表示可以按粗定位执行任务，但房间仍未确认。到达估计点后直接开启局部相机建图，在附近最多4m的可达区域转向搜索，接近和抓取均要求新鲜视觉检测。没有可用估计点时报告失败，不自动执行全图巡查。

普通 OctoMap 只有占用信息。全局 LiDAR 体素通过相机掩码投影及可见性 raycast 接收语义，结构化节点订阅 `/global_map/voxels`，将观测转换到 map 坐标，记录物体类别、位置及重复观测，再将全局二维地图和物体分布投影交给 VLM。YOLOE 三维检测作为补充。局部相机点云只在搜物/抓取阶段建图，给 MoveIt 提供碰撞场景，不作为探索地图。VLM 推断房间名称、候选 XY 范围、置信度和证据物体 ID；相机房间观察只作为辅助证据，观察者位置不直接等同于房间位置。跨重启复用 map 坐标下保存的 PCD、二维地图及匹配的语义摘要，不直接重载 odom 坐标体素快照。

VLM 使用 JSON Schema 约束输出房间枚举和已观测物体 ID；原始回复、输入地图图像保留供审查。候选分区须通过证据物体位置、置信度和最小面积检查，并与已知可通行栅格相交。`bounds_xy` 是候选包围盒，`cell_runs` 是筛选后的可通行区域。开放区域边界可能有歧义；单个杯子或可乐不足以断言厨房。几何连通分区保留作为基础能力，不能替代物体语义判断。

执行链路：保存地图并完成定位 → 查询已确认房间范围或 VLM 估计搜寻点 → Nav2 导航与实际到达核验 → 开启局部相机建图、机械臂进入观察姿态 → YOLOE 目标锁定与视觉伺服 → GraspNet／MoveIt 抓取、抬起、持物回 Home。已确认的房间区域保留到达后 VLM 核验；估计点不强制等待房间核验，以便先执行搜寻。

VLM估计搜寻点允许0.30m粗定位误差；进入范围后结束Nav2目标、核验底盘停稳，再交给视觉伺服，避免粗定位阶段在最后几厘米卡住。视觉伺服以10Hz读取RGB-D三维检测和`tracks_3d`，按实例ID与空间距离锁定同一目标，要求至少3个不同时间戳的稳定观测。最新观测年龄不得超过0.35秒；丢失后立即停止平移，只转向重新观测同一目标，不跳转历史地图目标。初次转向搜索限45秒，丢失重观测限8秒，总伺服限90秒；受到障碍阻挡无实际运动时停止并报告。

三维观测按图像采集时刻变换到odom，再使用新鲜底盘位姿闭环，避免异步全局配准延迟影响接近。当前视野预测使用最新且年龄≤0.35秒的相机TF；搜寻区域检查单独使用年龄≤1秒的map校正。感知端短暂等待精确采集时刻TF，不使用当前相机位姿转换旧图像观测。

接近速度上限0.12m/s、后退0.06m/s、转向0.30rad/s。伺服发布至原始`/cmd_vel_nav`，随后仍经过velocity_smoother → collision_monitor → `/x_bot/cmd_vel_nav` → localization_safety_gate；不直接向最终安全输出或手动优先话题发运动指令，也不与活动Nav2目标并行控制。进入0.62–0.76m候选距离、横向偏差≤5.5cm、朝向误差≤0.08rad、肩部坐标系(`fr3_link1`)半径0.80m的候选工作区，并且目标在相机有效视野内时停车。保持稳定、底盘停稳后再次核验新鲜目标，才允许抓取；最终抓取位姿和可达性由GraspNet／MoveIt核验。

状态：`/explore/status`、`/semantic_world/state`、网页 `/api/status`。结构化文件包含物体、房间、候选分区、相机观察和地图元信息。

定位模式的 `map_activation_guard` 会核验 `/map` 是否发布。若生命周期配置/激活回复丢失，它重新读取 `map_server` 的实际状态，再决定是否继续激活，不重复配置已激活的节点。语义节点即使尚未收到二维地图，也发布 `waiting_map` 健康状态；导航对缺少语义状态或二维地图最多等待10秒并报告原因，只有真实的 `running/saving/paused` 探索任务才进入长等待，同时向聊天界面发送阶段进度。网页状态中 `navigation_map_received` 和 `semantic_state_age_s` 可区分地图缺失与正常探索。

实测记录：全局 PCD 已保存 174,172 点，重启进入已有地图定位模式，未再次启动自动探索。首次完整任务在巡查与房间确认阶段失败，日志与视频位于 `log/semantic_navigation/validation`。2026-10-24 Gazebo单次“厨房拿可乐”复测通过VLM估计点交接、转向搜索、视觉伺服、抓取、抬高12cm、回Home及2秒夹持检查，总耗时约71秒。伺服阶段目标距离从1.045m收敛至0.724m，横向偏差约1.1cm、肩部距离0.797m；各级速度链路最终为零，抓取后相机中可见持握的红色可乐罐。前一轮在1.324m处丢失目标并停止，说明仍可能因视觉观测失败而中止。数据、进度和抓取后图像保存在本机 `.cache/visual_servo_validation/`。该单次测试不代表所有起点、遮挡及房间推断均已验证，已确认房间范围的完整导航流程仍待单独验收。
